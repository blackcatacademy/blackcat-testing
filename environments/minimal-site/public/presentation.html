What is BlackCat?

BlackCat is a modular security kernel for PHP websites. It replaces “trust the hosting” with a strict model: integrity + policy + runtime-config are committed and verified against an on-chain authority. When anything important diverges, the system fails closed.
  • On-chain integrity: the server refuses to operate if local disk is tampered (commitments are verified on a quorum of RPC endpoints).
  • Secrets boundary: the web runtime cannot read raw keys/DB creds; sensitive operations happen behind a local agent boundary.
  • Fail-closed enforcement: no “bypass switch” in production — unsafe writes/decrypts are blocked by default.
  • Auditable incident trail: anomalies queue anonymized incident intents/signature requests for relayers/watchers.
This demo proves the model by comparing an intentionally insecure control target with a protected target in the same stack.

What this demonstrates fail-closed on-chain trust secrets boundary auditable incidents
1) Without BlackCat, secrets leak
The unprotected control target can leak key material and DB credentials to anyone who can run code in the web runtime.
2) With BlackCat, bypasses are blocked
Even if an attacker reaches PHP, direct reads are blocked by OS permissions and the agent enforces TrustKernel before serving any sensitive operation.
3) On tamper, the kernel fails closed
When integrity/policy/runtime-config diverge, write_allowed=false immediately blocks writes, incidents can be queued, and operators can auto-pause on-chain.
